# Contributing to ULPO

Thank you for your interest in contributing to the Universal Linux Performance Optimizer (ULPO)! This document provides guidelines for setting up your development environment, compiling target binaries, running verification checks, and submitting changes.

---

## 🛠️ Developer Environment Setup

To compile and verify ULPO libraries locally on your host machine without container boundaries, you will need the following tools:

### Prerequisites (Debian/Ubuntu)
Install standard building and extraction dependencies:
```bash
sudo apt-get update && sudo apt-get install -y \
    build-essential \
    cmake \
    git \
    curl \
    file \
    xz-utils \
    llvm \
    autoconf
```

### Install Zig Compiler
ULPO uses the **Zig** toolchain as a unified cross-compiler. Download and link Zig (v0.16.0 stable) to your local path:
```bash
# Detect architecture and download
ZIG_ARCH=$(uname -m)
curl -Lo /tmp/zig.tar.xz "https://ziglang.org/download/0.16.0/zig-${ZIG_ARCH}-linux-0.16.0.tar.xz"
sudo tar -xf /tmp/zig.tar.xz -C /usr/local
sudo ln -sf /usr/local/zig-${ZIG_ARCH}-linux-0.16.0/zig /usr/local/bin/zig

# Setup helper compilation scripts (CMake bypass wrappers)
echo '#!/bin/sh\nexec /usr/local/bin/zig ar "$@"' | sudo tee /usr/local/bin/zig-ar > /dev/null
echo '#!/bin/sh\nexec /usr/local/bin/zig ranlib "$@"' | sudo tee /usr/local/bin/zig-ranlib > /dev/null
sudo chmod +x /usr/local/bin/zig-ar /usr/local/bin/zig-ranlib
```

## 📦 Building ULPO

We compile target libraries using two methods: **OCI Container Build** (recommended for release) and **Local Shell Orchestration** (recommended for rapid development iterations).

### 1. Container Builds (using Podman / Docker)

The multi-stage build automatically uses Zig inside the builder container to generate two different final target images.

#### Build the Release Image (Default, ~11.6 MB)
Contains only optimized, stripped production libraries (`/allocators` and `/compression`):
```bash
podman build -t ulpo:latest .
```

#### Build the Debug Image (~116 MB)
Contains both production libraries and unstripped versions under `/debug` with full symbols:
```bash
podman build --target debug -t ulpo:debug .
```

---

### 2. Local Host Builds (Fast Iterations)

You can run the build script directly on your host machine to compile specific targets into a staging directory:

1.  **Clone the dependencies** into a local `/src` directory (or modify the paths in `build.sh`):
    ```bash
    mkdir -p /tmp/src /tmp/build /tmp/stage
    git clone --depth 1 -b v3.3.2 https://github.com/microsoft/mimalloc.git /tmp/src/mimalloc
    git clone --depth 1 -b 2.2.4 https://github.com/zlib-ng/zlib-ng.git /tmp/src/zlib-ng
    git clone --depth 1 -b 5.3.1 https://github.com/jemalloc/jemalloc.git /tmp/src/jemalloc
    ```
2.  **Execute the build script** by redirecting output paths:
    ```bash
    # Override paths for local testing
    SRC_DIR="/tmp/src" BUILD_ROOT="/tmp/build" ./build.sh /tmp/stage
    ```

## ⚙️ Compilation Target Matrix

The pipeline compiles every library against 8 cross-compilation target triplets in [build.sh](file:///home/gheffern/Projects/ULPO/build.sh):

*   `x86_64-linux-gnu.2.28` (glibc-2.28, amd64)
*   `x86_64-linux-gnu.2.34` (glibc-2.34, amd64)
*   `x86_64-linux-gnu.2.39` (glibc-2.39, amd64)
*   `x86_64-linux-musl` (musl libc, amd64)
*   `aarch64-linux-gnu.2.28` (glibc-2.28, arm64)
*   `aarch64-linux-gnu.2.34` (glibc-2.34, arm64)
*   `aarch64-linux-gnu.2.39` (glibc-2.39, arm64)
*   `aarch64-linux-musl` (musl libc, arm64)

These compile outputs map directly to `/<lib_type>/<lib_name>/<libc>/<arch>/` inside the staging directories.

## 🛡️ Quality Gates & Verification

The compilation script automatically calls [verify.sh](file:///home/gheffern/Projects/ULPO/verify.sh) after each target is built. A pull request must pass all four quality checks:

1.  **GLIBC Version Compatibility Limit**:
    *   Verifies that the compiled binary does *not* contain versioned symbol references that exceed its target API ceiling (e.g., checking that a `glibc-2.28` compiled binary contains no `GLIBC_2.29+` dependencies).
2.  **Dependency Isolation Verification**:
    *   Asserts that no dynamic links exist for C/C++ helper libraries (such as `libgcc_s.so` or `libstdc++.so`), ensuring maximum portability across containers. Linkers are forced to compile these statically (`-static-libgcc`).
3.  **Instruction Set Check (Intel Targets)**:
    *   Checks x86-64 builds of `zlib-ng` to verify that carryless multiplication (`pclmul`) vector instructions were successfully generated by the compiler.
4.  **Smoke-test preloading**:
    *   Performs a runtime test preloading the binary against standard utilities (`true`, `python3`) on host systems with matching architectures to guarantee no crash/segfault occurs.

## ➕ Adding a New Performance Library

To add a new library (e.g., `tcmalloc`) to the ULPO matrix, follow these steps:

1.  **Cloning Configuration**: Add a version build-argument and clone target in the [Dockerfile](file:///home/gheffern/Projects/ULPO/Dockerfile).
2.  **Build Orchestration**: Add compile instructions in [build.sh](file:///home/gheffern/Projects/ULPO/build.sh). Follow the wrapper configuration pattern:
    *   Use `$CC`, `$CXX`, `$AR`, and `$RANLIB` wrappers.
    *   Disable host-specific compiler optimization structures (i.e. do *not* compile with `-march=native`).
    *   Statically link GCC support helpers (`-static-libgcc`).
    *   Stage the stripped binaries into `allocators/` or `compression/` and the unstripped binaries into `debug/`.
3.  **Documentation**: Update the path layout and auto-detection scripts in the [README.md](file:///home/gheffern/Projects/ULPO/README.md).
4.  **Commit Guidelines**: Use descriptive commit tags matching your feature additions (e.g., `Add tcmalloc configuration`).
